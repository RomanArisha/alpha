# Indoor Positioning System (IPS)

MVP-система для определения координат объектов внутри помещения по уровню сигнала RSSI от нескольких сканеров.

## Возможности

- Получение измерений RSSI через MQTT.
- Преобразование RSSI в оценку расстояния до сканера.
- Расчёт координат методом трилатерации.
- Фильтрация выбросов и сглаживание координат.
- Отображение сканеров и меток на SVG-карте помещения.
- Получение актуальных координат через WebSocket.
- Эмуляция двух меток для тестирования без реального оборудования.

## Стек технологий

**Backend:**
- Python 3.10+
- FastAPI — HTTP API и WebSocket.
- aiomqtt — асинхронное взаимодействие с MQTT.
- Paho MQTT — публикация сообщений эмуляторами.
- NumPy — математические вычисления.
- SciPy — оптимизация при трилатерации.
- Pydantic — модели и валидация данных.
- Uvicorn — запуск ASGI-приложения.

**Frontend:**
- HTML
- CSS
- JavaScript (ES Modules)
- SVG

**Инфраструктура:**
- Eclipse Mosquitto — MQTT-брокер.

## Установка

### 1. Установить Python

Рекомендуется Python 3.10 или новее.

Проверить установку:

```bash
python --version
```

### 2. Создать виртуальное окружение

Из корневой папки проекта:

**Windows:**

```powershell
python -m venv .venv
.venv\Scripts\activate
```

**Linux/macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Установить зависимости

Создай файл `requirements.txt` со следующим содержимым:

```text
fastapi
uvicorn[standard]
aiomqtt
paho-mqtt
numpy
scipy
pydantic
```

Установи библиотеки:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Все Python-зависимости устанавливаются в виртуальное окружение. Node.js и npm для текущего frontend не требуются.

## Установка и запуск Mosquitto

Mosquitto — отдельная программа, выполняющая роль MQTT-брокера. Установка Python-библиотеки `paho-mqtt` или `aiomqtt` не заменяет установку самого брокера.

В текущей конфигурации backend и оба эмулятора подключаются к:

```text
Host: localhost
Port: 1883
```

### Windows

1. Установи Eclipse Mosquitto с официального сайта: https://mosquitto.org/download/
2. После установки открой терминал в папке Mosquitto либо добавь путь к `mosquitto.exe` в `PATH`.
3. Запусти брокер:

```powershell
mosquitto -v
```

Если Mosquitto установлен как служба Windows, можно запустить её из PowerShell от имени администратора:

```powershell
Start-Service mosquitto
```

Проверить статус службы:

```powershell
Get-Service mosquitto
```

Если служба уже запущена, второй экземпляр на том же порту запускать не нужно.

### Ubuntu/Debian Linux

Установка:

```bash
sudo apt update
sudo apt install mosquitto mosquitto-clients
```

Запуск и включение автозапуска:

```bash
sudo systemctl enable --now mosquitto
```

Проверка:

```bash
sudo systemctl status mosquitto
```

При необходимости запустить брокер вручную в терминале:

```bash
mosquitto -v
```

Не запускай ручной экземпляр, если системная служба уже занимает порт 1883.

### Проверка MQTT

В отдельном терминале подпишись на сообщения:

```bash
mosquitto_sub -h localhost -p 1883 -t "ips/scanners/+/rssi" -v
```

Когда эмулятор заработает, в терминале появятся сообщения с RSSI.

В текущей конфигурации используется локальное подключение без настройки авторизации. Не открывай такой брокер в интернет без настройки безопасности.

## Запуск приложения

Все команды ниже выполняются из корневой папки репозитория.

### 1. Запустить MQTT-брокер

Убедись, что Mosquitto запущен и слушает порт `1883`.

### 2. Запустить backend

Активируй виртуальное окружение и выполни:

```bash
python -m uvicorn backend.main:app --reload
```

Backend будет доступен по адресу:

http://127.0.0.1:8000

Документация API:

http://127.0.0.1:8000/docs

При запуске приложение создаёт фоновую задачу, которая подключается к MQTT и подписывается на топик:

```text
ips/scanners/+/rssi
```

### 3. Запустить первый эмулятор

Открой второй терминал в корне проекта, активируй виртуальное окружение и выполни:

```bash
python emulator.py
```

Он имитирует метку `tag-001` с координатами `(6, 3)`.

### 4. Запустить второй эмулятор

Открой третий терминал и выполни:

```bash
python "emulator 2.py"
```

Он имитирует метку `tag-002` с координатами `(15, 9)`.

Оба эмулятора публикуют измерения для трёх сканеров каждые 0,5 секунды.

### 5. Открыть интерфейс

Открой в браузере:

http://127.0.0.1:8000

На карте должны отображаться сканеры и обнаруженные метки. При выборе объекта справа показывается информация о нём.

Останавливать эмуляторы и backend можно сочетанием `Ctrl+C` в соответствующих терминалах.

## Последовательность запуска

1. Mosquitto — MQTT-брокер.
2. Backend — API, обработка измерений и WebSocket.
3. `emulator.py` — первая метка.
4. `emulator 2.py` — вторая метка.
5. Открыть frontend в браузере.

Эмуляторы можно запускать в любом порядке после старта брокера. Для получения координат необходимы измерения как минимум от трёх сканеров для одной метки.

## API

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/api/scanners` | Получить список сканеров |
| GET | `/api/map` | Получить параметры карты |
| GET | `/api/map/file` | Получить SVG-карту |

| WebSocket | `/ws/tags` | Получать актуальные координаты меток |

## Описание основных файлов

### Backend

**`backend/main.py`**
- Создаёт FastAPI-приложение.
- Загружает конфигурацию сканеров из JSON.
- Предоставляет API для карты и сканеров.
- Запускает MQTT-обработчик в фоновой задаче.
- Передаёт координаты меток клиентам через WebSocket.

Основные функции: `lifespan()`, `get_scanners()`, `get_map()`, `get_map_file()`, `tags_websocket()`.

**`backend/mqtt.py`**
- Подключается к Mosquitto.
- Получает и проверяет сообщения RSSI.
- Преобразует RSSI в расстояние.
- Собирает измерения от сканеров.
- Вычисляет координаты, фильтрует их и обновляет состояние меток.
- Удаляет устаревшие данные и повторно подключается к брокеру при ошибках.

Основные функции: `mqtt_loop()`, `maintenance_loop()`.

**`backend/calculations.py`**
- `rssi_to_distance()` — преобразует RSSI в расстояние по модели потерь сигнала.
- `trilaterate()` — вычисляет координаты по расстояниям до сканеров с помощью численной оптимизации.
- `get_fresh_measurements()` — собирает актуальные измерения, хотя в текущем `mqtt.py` эта функция напрямую не используется.

**`backend/measurements.py`**

Класс `MeasurementStore` хранит последние измерения для каждой пары «метка — сканер», отбрасывает устаревшие данные и не принимает измерения с более старыми временными метками.

**`backend/position_buffer.py`**

Классы `PositionSample` и `PositionBuffer` хранят недавние оценки координат, отбрасывают слишком удалённые точки и рассчитывают устойчивую оценку по согласованным измерениям.

**`backend/kalman.py`**

Класс `Kalman2D` реализует двумерный фильтр Калмана с оценкой скорости. Сглаживает перемещение меток и отбрасывает измерения, сильно расходящиеся с прогнозом.

**`backend/models.py`**

Содержит Pydantic-модели `Position`, `Scanner`, `Tag`, `TagsUpdate` и `MapInfo` для проверки структуры данных и формирования ответов API.

**`backend/data/scanners.json`**

Конфигурация трёх сканеров: идентификаторы, названия, координаты и радиусы действия.

**`backend/data/map.svg`**

Векторная карта помещения, на которой отображаются сканеры и метки.

**`backend/__init__.py`**

Обозначает каталог `backend` как Python-пакет.

### Эмуляторы и вспомогательные файлы

**`emulator.py`**

Имитирует метку `tag-001`. Вычисляет расстояния от фиксированной позиции метки до трёх сканеров, генерирует RSSI с небольшим случайным шумом и публикует JSON-сообщения в MQTT.

**`emulator 2.py`**

Выполняет ту же задачу для метки `tag-002`, расположенной в другой точке помещения.

**`payload.json`**

Пример MQTT-полезной нагрузки с идентификатором метки и RSSI. В текущей конфигурации эмуляторы формируют сообщения самостоятельно, поэтому файл не используется автоматически.

**`script.py`**

Вспомогательный скрипт для сбора содержимого текстовых файлов проекта в `result.txt`. Путь `ROOT_DIR` сейчас задан для конкретной машины и должен быть изменён при переносе на другой компьютер. Самому приложению этот скрипт не требуется.

**`result.txt`**

Результат работы `script.py`; генерируемый вспомогательный файл.

### Frontend

**`frontend/index.html`**

Главная HTML-страница, содержащая контейнер карты, боковую панель и подключение JavaScript-модуля.

**`frontend/css/style.css`**

Определяет компоновку страницы, размеры карты и боковой панели, а также базовые стили SVG-элементов.

**`frontend/js/api.js`**

Функции `getMap()`, `getScanners()` и `getMapSvg()` загружают параметры карты, список сканеров и SVG-карту с backend.

**`frontend/js/main.js`**

Главный модуль интерфейса. Функция `init()` загружает данные, инициализирует карту, размещает сканеры, подключает WebSocket меток и обрабатывает выбор объектов.

**`frontend/js/map.js`**

Функция `loadMap()` вставляет SVG-карту в DOM и проверяет наличие корневого элемента `<svg>`.

**`frontend/js/scanners.js`**

Функции `renderScanners()` и `renderScanner()` отображают сканеры и их радиусы действия. `selectScanner()` выделяет выбранный сканер, `clearScannerSelection()` сбрасывает выделение.

**`frontend/js/tags.js`**

Функции `connectTags()`, `renderTags()` и `updateTagMarker()` обеспечивают получение координат через WebSocket и обновление положения меток. Также реализованы выбор метки и автоматическое переподключение WebSocket.

**`frontend/js/sidebar.js`**

Функции `renderScannerSidebar()`, `renderTagSidebar()` и `clearSidebar()` отображают информацию о выбранном объекте. `formatNumber()` форматирует координаты, `escapeHtml()` экранирует выводимые строки.

## Формат MQTT-сообщения

Топик:

```text
ips/scanners/scanner-1/rssi
```

Пример payload:

```json
{
  "tag_id": "tag-001",
  "rssi": -63
}
```

Идентификатор сканера извлекается из топика, а идентификатор метки и RSSI — из JSON.

## Устранение неполадок

**MQTT connection error**
- Проверь, что Mosquitto запущен.
- Убедись, что порт `1883` доступен.
- Проверь, что backend и эмуляторы используют одинаковые настройки подключения.

**Не появляются метки**
- Запусти минимум три сканера-эмулятора в смысле источников измерений для каждой метки. В данном проекте один эмулятор публикует данные сразу от трёх сканеров.
- Убедись, что сообщения приходят в топик `ips/scanners/+/rssi`.
- Посмотри сообщения backend: при недостаточном числе измерений, ошибке трилатерации или отсутствии консенсуса координаты не обновляются.

**Не открывается карта**
- Проверь наличие `backend/data/map.svg`.
- Проверь доступность `/api/map`, `/api/scanners` и `/api/map/file`.
- Посмотри ошибки в консоли браузера.

**Не устанавливаются зависимости**
- Убедись, что виртуальное окружение активировано.
- Проверь версию Python.
- Повтори установку командой `python -m pip install -r requirements.txt`.

## Ограничения текущей версии

- Позиции меток в эмуляторах фиксированы.
- Модель RSSI упрощённая и не учитывает реальные особенности помещения.
- Координаты зависят от правильности расположения сканеров в `scanners.json`.
- При запуске приложения требуется доступный MQTT-брокер.
- Для практического применения понадобятся калибровка RSSI, проверка точности и дополнительные испытания с реальным оборудованием.
